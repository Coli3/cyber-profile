# 升级与同步

> 项目是**源**，Obsidian 是**活库**。
> 两边的职责不一样：源可以整体替换，活库只能增量迁移。

---

## 一、两个位置

| 角色 | 路径 | 放什么 | 升级时 |
|---|---|---|---|
| **源** | `<包目录>` | 模板、技能、文档 | 只读，不动 |
| **活库** | `<你的活库目录>` | 你的档案 | **只增不覆盖** |

以前说的"零复制"是指搭建阶段。一旦你开始填内容，这两边就必须分开——
因为**复制等于覆盖**，而你的 `me.md`、`数字档案`、`经历` 里已经是你的字了。

---

## 二、为什么不能直接拷

假如以后我改了 `档案 profile/me.md` 的模板结构，你直接把它拷进活库：

```
你的 me.md（877 字节，写了你的在意什么、怎么跟你说话）
        ↓ 被覆盖
模板 me.md（913 字节，全是 ___ 占位符）
```

**你的内容没了，而且系统不会报错。** 这是最危险的一类事故——静默的。

---

## 三、升级分三类，处理方式完全不同

| 类型 | 例子 | 处理 |
|---|---|---|
| **结构新增** | 新增一个目录、一个新模板页 | **直接创建**，零风险 |
| **模板改进** | 给 L2 页加一个字段、给报告换骨架 | 对比基线 → 没改过的覆盖，改过的生成 `.new` |
| **规则变更** | `AGENTS.md` 加一条铁律 | **永远只生成 `.new`**，由你决定加不加 |

第三条为什么特殊：`AGENTS.md` 是这套系统的基本法，而且你可能自己改过它。AI 不该有权限悄悄改法。

---

## 四、三分支判定（升级的核心逻辑）

升级时对每个受管文件依次问三个问题，顺序不能乱：

```
① 新版模板和基线一样吗？
   └─ 一样 → 模板这次没改它 → 跳过（不管你改没改，都不打扰你）

② 不一样，那活库这个文件动过吗？（活库现状 vs 基线）
   ├─ 没动过 → ✅ 安全覆盖成新版
   └─ 动过   → ⚠️ 生成 文件名.new，不覆盖

③ 活库里压根没有这个文件 → ✅ 直接创建
```

关键在于第 ① 步：**模板没变的文件，一律不碰。** 否则你填过的 `me.md` 每次升级都会被误报成"冲突"，警报疲劳比覆盖更可怕。

基线存在 `活库/.history/升级基线/manifest.json`，记录**上次同步时模板的** sha256。
每次升级成功后更新——它就是"上次同步时长什么样"。

**数据文件不在受管范围**，永远不参与比对：

```
档案 profile/L1 情境 events/**      ← 你的记录
档案 profile/L2 行为 behavior/**
档案 profile/L3 认知 cognition/**
档案 profile/领域 domains/**
档案 profile/自我评价待核.md        ← 已填就归你
原始资料 raw/**
报告 reports/**
.history/**
知识库 wiki/资料摘要|实体|概念/ 里你新建的页
```

## 五、怎么升级（说一句「升级」就行）

流程固定六步：

1. **快照**：把受管文件复制到 `活库/.history/upgrade-YYYYMMDD-HHMM/`
2. **读基线**：`活库/.history/升级基线/manifest.json`
3. **逐文件三分支**：覆盖 / `.new` / 新建
4. **更新基线**：写入本次的新 hash（冲突文件保留你当前的 hash，等合并后再说）
5. **出报告**：覆盖 N 个、冲突 M 个（列出 `.new`）、新增 K 个、`AGENTS.md` 差异摘要
6. **提示重启会话**，让新的 `me.md` 与规则生效

---

## 六、`.new` 怎么合并

出现 `.new` 意味着两边都变了。三种处理：

| 方式 | 适合 |
|---|---|
| Obsidian 并排打开，手动搬 | 改动小，你清楚要什么 |
| 让 AI 做三方合并（基线 / 你的 / 新版） | 改动大，或你不确定哪边重要 |
| 直接删掉 `.new` | 新版那点改进你不用 |

合并完删掉 `.new`，下次升级会把你现在的版本记为基线。

---

## 七、技能升级是另一条线

技能和档案数据完全隔离，可以整体覆盖：

```bash
# WorkBuddy
cp -r "<包目录>/03 技能包/self-distill" ~/.workbuddy/skills/

# Codex（启动自动发现）
mkdir -p ~/.codex/skills && cp -r "<包目录>/03 技能包/self-distill" ~/.codex/skills/
```

**技能里没有任何你的数据**，所以这条路永远是"删了重拷"，不用想冲突。

版本对不对，看这几个地方：

```
<包目录>/03 技能包/self-distill/VERSION
~/.workbuddy/skills/self-distill/VERSION
~/.codex/skills/self-distill/VERSION
```

两个 `version:` 一致就是同步好了。

---

## 八、回滚

升级出问题，两条路：

1. 说「回滚 2026-10-21」（换成你要回到的日期），我从 `.history/` 找最近快照还你。
2. 手动：从 `.history/upgrade-YYYYMMDD-HHMM/` 把文件复制回去。

**升级前的快照永远不会被自动删除。**

---

## 九、一条铁律

> **升级只碰系统文件，永远不碰你的记录。**

判断标准很简单：**这个文件里有你写的字吗？** 有，就不覆盖。

---

## 十、第一次升级前

基线文件（`活库/.history/升级基线/manifest.json`）在**第一次说「升级」时建立**。
那一次没有基线可比，AI 会先把当前模板的指纹记下来，**不覆盖任何文件**；
从第二次起，才按第四节的三分支走。

所以第一次升级你会看到"新增 0 个、覆盖 0 个、冲突 0 个"——**这不是失败，是基线刚建好。**
