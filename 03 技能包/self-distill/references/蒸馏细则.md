# 蒸馏细则

一句话记住三档的区别：**周蒸馏看重复，月蒸馏看结构，季蒸馏看代价。**

---

## 通用原则

1. **增量编译，不重写。** 已有页面做修订，保留原证据行，新证据追加。
2. **候选必须过审。** 除批量模式外，L2 及以上落笔前要用户确认。确认是唯一的升级开关。
3. **被拒候选要留痕。** 报告里写「被拒列表」——这是校准 AI 判断力唯一的反馈信号。
4. **蒸馏不读原文全文。** 读 L1 与已有 L2/L3；证据存疑时才回原文核对该条。
5. **写前快照。** 修改任何 L2/L3/产出面之前，先复制到 `.history/`。
6. **收尾三件套**：更新目录 → 追加日志 → 写报告（月/季必写，周可选）。

---

## 零、摄入（把外部材料变成档案素材）

**触发**：`原始资料 raw/` 根目录里存在不在 `已摄入/` 中的文件；或用户说「摄入」。

```
1. 列清单：文件名 / 类型 / 大小 / 预估信息密度
2. 读：>5 万字的先抽样（开头、结尾、每章首段），不整篇载入
3. 写摘要页：知识库 wiki/资料摘要 sources/<标题>.md
4. 抽条目：按「导入式建档」的证据规则——简历/自述类一律 T4，不产 L2
5. 更新：目录 index → 健康 health 覆盖度 → 日志
6. 最后一步：把文件移入 原始资料 raw/已摄入/
7. 读不了的留在原地，写进报告说明原因
```

### 摘要页固定字段

```markdown
---
type: 资料摘要
来源: 简历2026.pdf
类型: 简历
日期: 2026-10-21
抽取等级: T4
填了维度: [决策方式, 工作方式]
tags: [资料摘要]
---

# 简历2026

## 一句话
（这份材料整体在说什么）

## 可入档条目
- 2023.03–2025.06 A 公司产品经理（→ 时间线）
- 主导订单系统重构（→ domains/交易，待核）

## 不可用 / 剔除
- 联系方式、身份证、薪资：按安全条款剔除

## 与既有档案的冲突
- 与日记时间线不一致：___
```

### 批量摄入（无人在场）

- 不提问、不等确认。
- 只写摘要页 + L1 候选，**L2 以上不落笔**。
- 出 `报告 reports/YYYY-MM-DD 摄入报告.md`。
- 移入 `已摄入/` 仍然放最后一步。

> 摄入与「导入式建档」是同一套证据规则的两个入口：一次性建库走导入式，日常补料走摄入。

---

## 一、捕获（每次对话 / 「记一下」）

### 判断链

```
这条是关于"我"的吗？
  ├─ 否 → 不记（信息查询、事务协作、AI 输出、公开知识）
  └─ 是 → 属于哪个维度？（十二维度里挑一个）
        → 证据等级？（T1–T7）
        → 已有同 subject 条目吗？
              ├─ 有 → 强化（+0.05，次数+1，更新最近强化）
              └─ 无 → 新建
        → 密级？（O/P/R，拿不准取高）
        → 写进当天 L1
        → 回执一行
```

### 回执格式

```
已记 L1 · 决策方式 · T2 (0.78) · 密级 O → 2026-10-21.md
```

一行就够。不要每次捕获都写一段总结——那会让用户关掉捕获功能。

### 密度控制

- 一天 **3–8 条**，超过 8 条说明判据太松。
- 只记：决策、情绪波动、立场鲜明的原话、新偏好、"本想 X 做了 Y"。
- 不记：事务性协作、纯信息交换、重复的日常寒暄。

### 当用户问"要不要记"

给判断，不要给选项清单：

> 「这条只能算 T6（顺口一提），我先记进 L1，但不会升级成结论。等它出现第三次再说。」

---

## 二、纠正（「不对」「我不会这样说」）

**秒级处理，不等复盘。** 完整流程见 `references/自进化协议.md` 第二节。三个要点：

1. 先复述你听到的纠正，确认没理解错。
2. 快照 → 改文件 → 写 `纠正日志` → 回执。
3. 同一方向连续 3 次 → **停手**，转 `待确认`。

---

## 三、周蒸馏

**范围**：`L1 情境 events/` 最近 7 天。

1. **清点**：列本周 L1 文件与条目数，报告覆盖区间。
2. **归并 subject**：按语义主题打桶（桶名＝未来的 L2 名）。
3. **数重复**：每桶条目数与时间跨度。
4. **过门槛**：≥3 次 且 跨 ≥14 天 且 ≥1 次真实决策。**三条缺一不可**。
5. **反例检索**：对每个候选执行三步法。
6. **生成候选表**。
7. **等确认**。
8. **落笔** → 更新目录 → 日志。

### 候选表格式

```markdown
### 本周 L2 候选（3 条）

| # | 条目名 | 维度 | 证据数 | 跨度 | 最高等级 | 建议置信度 | 反例 | 动作 |
|---|---|---|---|---|---|---|---|---|
| 1 | 决策前必须看到全貌 | 决策方式 | 4 | 10-06→10-19 | T2 | 0.78 | 1 条 | 新建 |
| 2 | 被临时改需求时先沉默后反问范围 | 情绪地形 | 3 | 10-08→10-18 | T1 | 0.80 | 无 | 新建 |
| 3 | 不喜欢开会 | 工作方式 | 2 | — | T6 | — | — | 观察中 |

**观察中**：能量低谷在周三下午（2 次，跨 9 天，未达跨度门槛）
**被拒列表**：无
```

## 四、月蒸馏

**范围**：本月 L1 + 全部 L2。

1. **L2 变动盘点**：新建、强化、轨迹该改的；**顺带回填 `命中` / `落空`**——上月做过的判断有没有应验，只按用户明确表态计（见 `自进化协议.md` 第三之二节）。
2. **找结构**：≥3 条 L2 指向同一原则的簇 → L3 候选。
   - 好：「在'质量 vs 速度'冲突中几乎总选质量，并愿意承担延期成本。」
   - 坏：「你是完美主义者。」——标签，不是结构。
3. **提炼框架**：反复出现的**做法**（不是性格）→ 更新 `框架 frameworks.md`。每条必须六项齐全。
4. **与 L4 对照**：新 L3 与 L4 冲突的，**不改 L4**，写进 `待确认` 的「L4 候选/张力」。
5. **重算衰减**：<0.15 转休眠。逐条列出，不静默处理。
6. **补时间线**：本月里程碑。
7. **更新健康指标**：覆盖度/准确率/新鲜度/张力数。
8. **出月报**：模板见 `references/报告模板.md` 第五节；必填「本期截面」。含新增、升级、降级/休眠、L4 候选、未解张力、下月建议观察的 3 个方向。
9. 目录 + 日志。

---

## 五、季蒸馏

**唯一能触碰 L4 的流程，且只能提案。**

1. **L3 复核**：支撑还成立吗？断了就降级或标 `衰退`。
2. **L4 候选**：从最稳的 L3 里挑，**最多 2 条**。
   - 每条必写：`主张 / 支撑的 L3 / 至少 1 个反例 / 一个能推翻它的未来场景`。
   - **写不出"能推翻它的场景"的，不是信念，是口号，不许提交。**
3. **写入** `待确认` 的「L4 候选」区块，明确说："这两条你自己抄进 `core.md`，我不代笔。"
4. **重生成五个产出面**：`me.md` / `说明书` / `声音` / `框架` / `分身` / `罗盘`，版本号 +1，页首标 `生成日期 / 样本量 / 覆盖区间`。
   - 罗盘按 `未来推演.md` 的解锁级别生成：覆盖度不够就少写一面，并在「本期推导不出来的」里说明缺哪个维度。**不许为凑满五面而硬推。**
   - 顺带跑 `复盘预测`：把到期押注逐条问过用户，写进账本，重算预测命中率。
5. **强制体检**（`自进化协议.md` 第五节）。
6. **出季报**：模板见 `references/报告模板.md` 第六节；必须含「三个月前 vs 现在」对照表，数据取自上一份季报的「本期截面」。

---

## 六、批量 / 无人在场

定时任务触发且用户不在场时：

- 全程不提问、不等确认。
- **只写 L1。** L2 以上一律不落笔——升级必须有人签字。
- 拿不准按保守处理：不确定是否记录 → 不记；不确定层级 → 放低一层。
- 密级 R 直接跳过，报告写"跳过 N 条，原因：密级"。
- 出 `报告 reports/YYYY-MM-DD 批量摄入报告.md`（模板见 `references/报告模板.md` 第八节）：处理条目数、写入文件、跳过原因、**待确认的 L2 候选表**。
- 日志追加并链接报告。

---

## 七、产出面重生成规则（校准）

| 产出 | 只读 | 禁止 |
|---|---|---|
| `me.md` | L4 + 当前 L3 + 说明书摘要 | 读原始对话 |
| `说明书 for-ai.md` | L2 / L3 / L4 | 无来源的建议 |
| `声音 voice.md` | L1 原话、语言特征 | 转述代替原话 |
| `框架 frameworks.md` | L3、domains、反复出现的打法 | 只写"是什么"不写"何时用" |
| `分身 persona.md` | 声音 + 性格 + L4 禁区，**只取密级 O** | 引用 P/R 内容 |

**每个产出生成后必过三检**：
1. 每条有没有来源指针（`← B-0007` 或原话引用）？
2. 有没有"任何人都适用"的句子？（有就删）
3. 读三句，用户能不能认出是自己？

---

## 八、失败与回滚

| 情况 | 处理 |
|---|---|
| 误把推断写成事实 | 该句后加 `「非原文·推断」`，置信度降到 ≤0.25，日志记更正 |
| 误改 L4 | 从 `.history/` 还原；无快照则请用户口述，**不自行推断原意** |
| 重复建了两个同义 L2 | 保留证据全的，另一页顶部 `已并入 [[X]]`，**不删**，从目录移除 |
| 用户明确否认 | 状态 `已推翻`，留原话，不再引用；同步检查引用它的 L3 与产出面 |
| 目录与文件不一致 | 以文件系统为准，重建对应区块 |
| 产物越写越长 | 按 token 预算裁剪：me ≤400、单页 ≤300、域 ≤1000 |
