# 接入与接线

档案最讽刺的失败方式：**你写了三千字，AI 一次也没读过。**

文件系统的真相是——`档案 profile/me.md` 只是硬盘上的一个文件。除非它被"挂"进会话上下文，否则对模型而言等于不存在。接线就是那个挂钩。

---

## 一、核心机制：不绑定代理，只绑定路径

档案不依赖任何特定工具。它靠**宿主指令文件**里的一个指针被加载：

```markdown
<!-- self-profile:start -->
## 关于我

@/绝对路径/档案 profile/me.md

需要更深信息时，按 `档案 profile/目录` 的索引按需读取，不要一次性全量加载。
优先级：me.md → L3 → 声音/框架 → L2 → 证据层（仅在核实时）。
<!-- self-profile:end -->
```

- 指针用**绝对路径**，不要相对路径（宿主工作目录经常变）。
- `<!-- self-profile:start/end -->` 是**托管块边界**。重跑只替换块内内容，块外一个字节都不动。这是幂等的关键。
- 只接线**磁盘上真实存在**的文件。跳过的文件不加指针——写了假指针比没写更糟。

---

## 二、宿主与指令文件

| 宿主 | 用户级（推荐） | 项目级 |
|---|---|---|
| **Codex** | `~/.codex/AGENTS.md`（Windows：`%USERPROFILE%\.codex\AGENTS.md`） | `<vault>/AGENTS.md` |
| **WorkBuddy** | `~/.workbuddy/AGENTS.md`（若存在） | `<vault>/AGENTS.md` |
| Claude Code | `~/.claude/CLAUDE.md` | `<vault>/CLAUDE.md` |
| GitHub Copilot | `~/.copilot/copilot-instructions.md` | `.github/copilot-instructions.md` |
| Cursor | — | `.cursor/rules/self-profile.mdc` |

**优先用户级。** 档案应该到处可用，而不是绑死在一个仓库里。

> ⚠️ **Codex 的全局路径是 `~/.codex/AGENTS.md`，不是 `~/.agents/AGENTS.md`。**
> 写错目录不会报错，只会静默失效——这是本文件最容易踩的坑。另外若存在 `~/.codex/AGENTS.override.md`，它**优先于** `AGENTS.md`。

本项目的 Obsidian vault 根目录已有 `AGENTS.md`，所以**最简单的一条路**是：直接往 `<vault>/AGENTS.md` 追加托管块。Claude Code、Codex、WorkBuddy 都读它。

---

## 二之二、Codex 与 WorkBuddy 逐项对比

两个宿主都认 `AGENTS.md`，但加载方式有实质差别，接线时要区别对待。

| | Codex | WorkBuddy |
|---|---|---|
| 全局指令文件 | `~/.codex/AGENTS.md`（`AGENTS.override.md` 优先） | `~/.workbuddy/AGENTS.md`（若存在） |
| 项目指令文件 | `<vault>/AGENTS.md`，从仓库根逐层向下合并 | `<vault>/AGENTS.md` |
| 合并上限 | 单次合并 **32 KiB**（`project_doc_max_bytes`） | 无硬上限，但越长越容易被稀释 |
| 冲突裁决 | 越靠近当前目录的文件越优先 | 以当前工作区为准 |
| 技能目录 | `~/.codex/skills/<name>/SKILL.md`，启动自动发现 | `~/.workbuddy/skills/<name>/SKILL.md` |
| 技能调用 | `$self-distill` 显式调用，`/skills` 列出全部 | 按 `description` 自动匹配 |
| `@路径` 展开 | **不保证展开**——它把 AGENTS.md 当纯文本注入 | 支持 `@绝对路径`，会直接注入文件内容 |

**最后一行决定了接线块怎么写：** 托管块里既保留 `@绝对路径`（WorkBuddy 直接吃），又写明"若未自动展开，请用读文件工具打开这个路径"（给 Codex 兜底）。两种宿主共用同一块文本，不需要维护两份。

**Codex 的目录选择**：在一个 vault 里用 Codex，`cd` 到 vault 再启动，`<vault>/AGENTS.md` 自动生效。但如果想在**任意项目**里都让 Codex 认识你，必须往 `~/.codex/AGENTS.md` 另写一份托管块——项目级的不会跨目录生效。

## 三、写入流程

```
1. 探测：哪些宿主指令文件存在？
2. 选定目标（用户级优先；已有托管块的文件优先续写）
3. 备份：cp <file> <file>.bak-YYYYMMDDHHMMSS
4. 判定三种情形：
   a. 文件不存在 → 用 assets/AGENTS-block.md 建文件 + 写托管块
   b. 文件存在但无托管块 → 追加到末尾（前面空一行）
   c. 已有托管块 → 只替换 start/end 之间
5. 复核：读回刚写的块，确认路径存在且可读
6. 告知用户：接了几个宿主、跳过了哪些、备份在哪
```

### 幂等要求

同一份档案连续接线两次，文件内容必须完全一致（除备份文件名外）。若第二次产生 diff，说明块边界识别有问题——停下来查，不要继续写。

## 四、状态自检（每次会话开场）

不看"有没有写过"，看"这一次读到了没有"。

| 状态 | 判定方法 | 处理 |
|---|---|---|
| `PRESENT` | 上下文里能读到 `me.md` 的实际内容，且无 `<!-- TODO -->` | 直接用 |
| `PRESENT-BUT-STUB` | 内容在，但关键字段仍是占位符 | 只问缺的字段，原地补 |
| `REFERENCED-MISSING` | 指令文件里有 `@路径`，但磁盘无文件 | 提议重建（可能是换了电脑/同步没到） |
| `NOT REFERENCED` | 上下文里没有任何痕迹 | 一句话提示接线，别啰嗦 |

**占位符识别**：`<!-- TODO -->`、`<!-- your name -->`、`___`、`（待填）`、空的二级标题。
一个只有标题没有内容的 `me.md`，状态是 `STUB` 而不是 `PRESENT`——假装读到了比没读到更危险。

## 五、常见故障

| 症状 | 原因 | 修法 |
|---|---|---|
| AI 像第一次见你 | 指针没生效 / 宿主不读该文件 | 换宿主文件或改用块内联全文 |
| 每次都要重新解释 | `me.md` 太长被截断 | 压到 400 token 内，细节移到按需层 |
| 档案更新了 AI 还记旧的 | 会话是旧上下文 | 新开会话，或让 AI 重读 `me.md` |
| 块被重复插入 | 未识别已有块 | 先 grep `self-profile:start` 再写 |
| 路径带空格失效 | 未加引号/未转义 | 路径整体用 `@"/abs/path with space.md"` |
| 换电脑后全丢 | 绝对路径变了 | 重新跑一次 `接线`，覆盖旧块 |

## 六、安全

- 托管块内**不放**凭据、密钥、身份证号、住址门牌。
- 改宿主文件前必须备份；**绝不删除**任何已有内容，只增改块内区间。
- 用户拒绝接线时，尊重选择，只在本次会话里临时读取 `me.md`（如果用户愿意）。
- 用户机器上有多个 vault 时，`me.md` 指针只指向**一个**——多份档案等于没有档案。

---

## 七、一句话

接线不是一次性安装，是**每次开口前的确认**。
就像出门前摸一下口袋有没有钥匙——三十秒的事，但没做，你就被锁在外面了。
